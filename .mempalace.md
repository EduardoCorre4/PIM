## Sprint 3 — situação detalhada (registrado em 2026-10-30)

Funcional e validado no backend e na lógica do app:
- Refresh token com rotação e revogação por reuso: `POST /api/auth/refresh`, `POST /api/auth/logout`.
- Chave de idempotência em `POST /api/chamados` (índice único por cliente): reenvio nunca duplica.
- `GET /api/meus-contratos` (somente Cliente).
- Lógica do app em `mobile/src/core` (cliente HTTP com renovação única, fila persistente, sincronização, cache): 24 testes unitários passando e 2 testes de integração passando contra a API real.
- Tipos (`tsc`) sem erros e empacotamento Android (`expo export`) sem erros.

**Pendente (decisão do usuário: fica para depois):** validação visual do app em emulador ou aparelho (Expo Go).
Telas ainda não vistas rodando: Login, Dashboard, Novo chamado (3 passos), Lista e Detalhe de chamados, comportamento da barra de conexão.

Observação de segurança já aceita: tokens ficam no SecureStore (criptografado pelo sistema); cache e fila ficam no AsyncStorage sem criptografia própria e são apagados no logout.

## Decisões de arquitetura (valem para as próximas sprints)

- Back-end em camadas: `Jake.Api` (apresentação) → `Jake.Service` → `Jake.Repository` → `Jake.Domain`. Service não acessa o banco diretamente.
- SQL Server + EF Core (migrations em `backend/src/Jake.Repository/Migrations`; scripts em `database/`).
- Regra de vigência do contrato existe no Service **e** na `sp_AbrirChamado`.
- Web (React + Vite) e mobile (Expo) consomem os mesmos endpoints REST.

## Ambiente local

- `docker compose up -d --build` sobe banco, API (:8080) e web (:3000). Variáveis em `.env` (modelo: `.env.example`).
- No WSL deste ambiente falta `libicu`: `dotnet` fora do Docker exige `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` e não conecta ao SQL Server.
- Existem dados de teste no banco local (clientes `c1@t.com`, `c2@t.com`); `docker compose down -v` limpa.
